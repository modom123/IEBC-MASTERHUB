# T12 Teacher Guide: Build Your Business Hub in 6 Weeks

| | |
|---|---|
| **Format** | 6 weekly live sessions (90 min) + weekly office hours (60 min), recorded |
| **Group size** | Up to 12 |
| **Level** | Intermediate |
| **Demo business** | Lakeside Home Services |
| **Student deliverable** | A live business hub (CRM, invoicing, reporting) with their team trained on it |

## What makes this cohort different

Students follow IEBC's own 6-week delivery framework (Discovery → Architecture → Build →
Testing → Launch) on their own business, with coaching. Each student has a **written scope
signed off by the teacher before building** (end of week 2), just like an IEBC client build.

**Teacher qualifications:** must have delivered at least one IEBC hub build, or co-teach with
someone who has. Teachers pick one no-code platform for the cohort (a database-style
spreadsheet or app builder) and every student uses it, so help is shareable.

★ **Scope control rule:** students build the 3 core modules (CRM/pipeline, invoicing,
reporting) first. Nothing else until those work. This is the #1 reason students finish or don't.

---

## Week 1: Discovery

**Objective:** Every student maps their workflows and pain points.

| Time | Segment |
|---|---|
| 0:00–0:10 | Welcome, framework overview, how sign-offs work |
| 0:10–0:30 | SHOW ★ Workflow mapping: lead → quote → job → invoice → payment → follow-up. Map Lakeside's on screen (boxes and arrows); mark every place data is re-typed (red) and every place something gets forgotten (orange). |
| 0:30–0:40 | TRY: map one Lakeside variation in pairs |
| 0:40–0:45 | Break |
| 0:45–1:15 | BUILD: students map their own business. Teacher reviews each map for 2–3 minutes in turn. |
| 1:15–1:25 | SHARE: 2 maps; group spots red/orange points |
| 1:25–1:30 | Assignment: complete map + list of the 10 pieces of information they track (customers, jobs, invoices…) |

## Week 2: Architecture

**Objective:** Every student has a written scope approved by the teacher.

★ MUST TEACH:
1. Data design: tables (Customers, Jobs/Deals, Invoices, Tasks), the fields in each, how they link.
2. One source of truth: every piece of information lives in exactly one place.
3. Permissions: who can see and edit what.
4. Scope document: modules, fields, automations, reports, out-of-scope list.

**SHOW:** Lakeside's table design and one-page scope.
**BUILD:** Students write their scope with the template.
**Sign-off:** teacher reviews each scope before week 3 (written feedback within 48 hours). ★ Push back on scope creep.

## Weeks 3–4: Build

**Objective:** CRM/pipeline and invoicing built and connected (week 3); reporting and automations (week 4).

**Week 3 session:** SHOW building Lakeside's Customers and Jobs tables and a pipeline view;
TRY on demo data; BUILD their own; SHARE.
**Week 4 session:** SHOW invoices linked to jobs, an overdue view, a weekly report and 2
automations (new lead alert, invoice reminder); BUILD; SHARE.

★ MUST TEACH across both weeks: build with sample data first, then import real data; keep
field names consistent; test every automation 3 times; ★ back up data before imports.

**Watch for:** students adding modules outside scope; importing messy spreadsheets without
cleaning (teach a 15-minute cleanup: one row per record, consistent dates, no merged cells).

## Week 5: Testing

**Objective:** Every hub passes a test script with real data.

★ MUST TEACH: write a test script (10 real scenarios: new lead, quote accepted, job done,
invoice sent, partial payment, cancellation…), run it, log issues, fix the top 3. Have one
other person (team member or classmate) run it too.

## Week 6: Launch and training

**Objective:** Hub live; team trained; 52-week roadmap written.

★ MUST TEACH: launch checklist (data imported, old system frozen, permissions set, backups on);
a 30-minute team training using the Build-Along arc (students practice teaching it in pairs);
a 52-week roadmap (quarterly improvements).
**Demo day:** each student shows their hub (3–4 minutes).

## Rubric

| | Not yet | Meets | Strong |
|---|---|---|---|
| Scope | Not signed off | Signed off; core modules only | Includes clear out-of-scope list |
| Build | Core modules incomplete | CRM, invoicing, reporting working and linked | Plus 2+ tested automations |
| Testing | No test script | 10-scenario script run, top issues fixed | Run by a second person too |
| Launch | Not live | Live with team trained | Plus 52-week roadmap |

## Office hours

Weekly 60 minutes. Priority to students who are behind schedule. Teacher keeps a simple
tracker: each student's phase vs. the cohort's week.
